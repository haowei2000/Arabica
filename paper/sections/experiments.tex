\subsection{Research Questions}

We deliberately narrow the evaluation to questions that the released
artifact can answer reproducibly.
\textbf{RQ1.} On long-term memory and context-selection benchmarks,
does path-addressable multi-level disclosure reach a better
accuracy--token trade-off than full-context and retrieval baselines?
\textbf{RQ2.} How much context does \textsc{Structure} select relative
to the available workspace state, and how does this affect tokens per
scored point?
\textbf{RQ3.} Do the two implemented feedback mechanisms---source
ratings and event-level garbage collection---change retrieval
evidence, token cost, or latency in sampled runs?
\textbf{RQ4.} Is the benchmark harness itself reproducible across
dataset adapters, scorers, external baseline registries, and paper
tables?

\subsection{Datasets and Benchmarks}

The main paper no longer claims coverage across the full agent
benchmark landscape. Instead, we evaluate the context-layer hypothesis
on three memory-focused benchmarks whose inputs expose the exact
choice our method targets: read all available state, retrieve a flat
top-$k$ subset, or navigate an addressable workspace at a chosen
disclosure level. LongMemEval measures long-term conversational memory
over ability-tagged questions; LoCoMo measures multi-session memory
over conversational histories; LongMemEval-V2 follows the newer
Insert/Query memory-system formulation over agent environment
trajectories. Broader task benchmarks such as AgentBench, WebArena,
OSWorld, AppWorld, SWE-bench, and $\tau$-bench are treated as future
generalisation targets rather than evidence for the current claim.

\subsection{Baselines}

We use two baseline tiers. The first tier compares \textsc{Structure}
against native baselines implemented in the released harness.
\textbf{(B1) FullText / flat window.} All available memory chunks are
materialised into the reader prompt, subject to the configured
context-character cap. This represents the simplest long-context
strategy and corresponds to the runner method \texttt{FullText}.
\textbf{(B2) NaiveRAG / top-$k$ retrieval.} The same state is split
into chunks and the top-$k$ chunks most similar to the current question
are materialised. This corresponds to the runner method
\texttt{NaiveRAG}.
\textbf{(B3) StructurePathMemory.} The reader model sees only the
context selected by the path-addressable workspace adapter, preserving
path metadata and disclosure/evidence diagnostics. This corresponds to
\texttt{StructureMemory} or \texttt{StructurePathMemory}. All live runs
use the same reader model, deterministic scorer, temperature, and case
sample; only context selection differs.

The second tier aligns the evaluation with the LightMem/MemBase memory
suite~\citep{fang2026lightmem}. We track the LoCoMo-reported FullText,
NaiveRAG, A-MEM, MemoryOS, Mem0, Mem0(api), and Mem0-g(api) rows as
external reference baselines, and we keep MemBase-supported LangMem,
EverMemOS, HippoRAG2, and Long-Context entries in the code registry so
newly reported rows can be added without changing the paper pipeline.
These external numbers are used for benchmark calibration only; new
\textsc{Structure} runs are always reported separately.

\subsection{Implementation Details}

The released runner reads \texttt{OPENAI\_\_API\_KEY},
\texttt{OPENAI\_\_BASE\_URL}, and \texttt{OPENAI\_\_MODEL}; the
reported model name is copied into every JSON result file. Unless
otherwise stated, live runs use temperature $0$, top-$k=6$, a maximum
materialised context of $120{,}000$ characters, deterministic
benchmark-specific scorers, and hash-based case sampling for stable
subsets. We report the exact sample size, source split size, prompt
tokens, completion tokens, latency, evidence summary, selected chunks,
available chunks, and per-case diagnostics. The CI-friendly validation
workflow runs without an LLM and verifies adapter/scorer correctness;
performance claims are made only from live JSON outputs produced by
\path{benchmarks/scripts/run_full_memory_benchmark.py}.

\subsection{Evaluation Metrics}

\paragraph{Task accuracy.} Benchmark-native success rate (higher is
better). LongMemEval reports per-ability accuracy; LoCoMo uses the
released QA scorer; LongMemEval-V2 blends answer correctness with
supporting-evidence recall.

\paragraph{Token cost.} Mean prompt and completion tokens per
trajectory, reported separately because prompt tokens dominate for
long-context agents (lower is better).

\paragraph{Latency.} Wall-clock time per trajectory, with per-case
diagnostics retained in JSON/JSONL artifacts.

\paragraph{Context efficiency.} Selected context chunks and selected
context tokens divided by available chunks/tokens. Lower ratios
indicate stronger compression at comparable accuracy.

\paragraph{Decision rule.} We treat a result as supporting the paper
claim only if \textsc{Structure} improves tokens per scored point at
comparable accuracy on at least two of the three narrowed benchmarks.
